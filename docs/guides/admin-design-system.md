# 광고센터 화면 결정 사항

> **디자인 시스템이 아닙니다.** 컴포넌트·토큰·타이포는 원본 시스템에 있습니다:
>
> ```
> .claude/skills/adcenter-design-system/
> ```
>
> 이 문서에는 그 시스템이 답하지 않는 것 — **이 제품이 무엇을 만들고 어떤 칸을
> 받는가** — 만 남깁니다.

## 이 문서를 이렇게 나눈 이유

전에는 여기에 컬러·타이포·컴포넌트 스펙을 함께 적어뒀습니다. 2026-08-11 감사에서
그중 **8곳이 원본과 달랐습니다**:

| 여기 적혀 있던 것 | 원본 |
|---|---|
| 에러 배경 `#fff4f4` | `#fff0f0` (`field/bg error`) |
| LNB 1depth `22/30` | `20/30`. 22px은 텍스트 스타일 12종에 없음 |
| "Outline 버튼 48~54" | 원본에 Outline 변형 자체가 없음 |
| 목록 안내문 `--color-ink-muted` | `ico&text/black` 100% |
| 스케일 표에 `24/35` 누락 | 모달 타이틀이 24/35인데 표에 없어 정상 코드가 위반으로 잡힘 |

머리말의 *"스크린샷 기반 추정치"* 경고가 Figma 실측 교체 후에도 남아 있었고,
그걸 읽고 사이드바를 검정으로 잘못 만든 적도 있습니다.

**한 규칙이 두 곳에 있으면 반드시 갈라집니다.** 그래서 겹치는 부분을 전부 지웠습니다.

## 1. 전체 플로우 (3단계)

```
1. 캠페인 만들기
   광고 상품(Fit 배너 / Full Screen 배너) 선택 → 캠페인 이름, 카테고리 지정
        ↓ "등록하고 광고그룹 만들기"
2. 광고그룹 만들기
   타겟팅, 집행 기간/시간, 예산(그룹 예산 / 일 예산) 설정
        ↓ "등록하고 소재 만들기"
3. 소재 만들기
   카피(메인/서브/안내문구), 이미지, 랜딩URL, 심사 참고사항 입력 → 미리보기 확인
        ↓ "등록하고 심사 요청하기"
```

우리 서비스(`adcenter-register` 스킬)는 이 3단계 중 **3단계 "소재 만들기"** 폼을 API/자동화로 채우는 것이 핵심 타깃입니다. 1~2단계(캠페인/광고그룹)는 광고주가 이미 만들어둔 것을 전제로 하거나, 추후 자동화 범위를 논의합니다.

## 2. 화면별 필드 정의

### 2-1. 캠페인 만들기
| 필드 | 타입 | 필수 | 제약 |
|---|---|---|---|
| 광고 상품 | 라디오 (Fit 배너 / Full Screen 배너) | ✓ | 우측에 상품별 미리보기 표시 |
| 캠페인 이름 | 텍스트 | ✓ | 25자 |
| 카테고리 | 2단계 depth 드롭다운 | ✓ | 대분류(교육/교통/금융/레저스포츠/반려동물/뷰티미용/생활서비스/쇼핑/온라인쇼핑/숙박/여행 등) → 소분류 |

### 2-2. 광고그룹 만들기
| 필드 | 타입 | 필수 | 제약 |
|---|---|---|---|
| 광고그룹 이름 | 텍스트 | ✓ | 25자 |
| 타겟팅 | 체크형 선택 (맞춤타겟 / 데모그래픽, 둘 중 하나만) | - | 맞춤타겟은 "카카오페이 광고 담당자로부터 전달받은 맞춤타겟 번호" 입력 방식 (툴팁 안내) |
| 집행 기간 | 날짜 범위 (시작일 - 종료일) | ✓ | 캘린더 피커 |
| 집행 시간 | 라디오 (모든 시간 / 요일별 시간대 설정) | ✓ | |
| 광고그룹 예산 (VAT 제외) | 숫자 입력 + 원 단위 표시 | ✓ | 캠페인 잔여 예산 이하 |
| 일 예산 (VAT 제외) | 숫자 입력 | ✓ | 광고그룹 예산 이하 |

### 2-3. 소재 만들기 (Fit 배너 기준)
| 필드 | 타입 | 필수 | 제약 |
|---|---|---|---|
| 소재 이름 | 텍스트 | ✓ | 25자 |
| 메인 카피 | 텍스트 | ✓ | **14자** (공백 포함) |
| 서브 카피 | 텍스트 | - | **15자** (공백 포함) |
| 안내 문구 | 텍스트 | - | 60자 (심의필 등 법적 고지용) |
| 이미지 | 파일 업로드 | ✓ | PNG, 500KB 이하, **240×240px** |
| 랜딩URL | URL 텍스트 | ✓ | `https://` 형식 |
| 심사 참고사항 | 텍스트영역 | - | 500자 |

> ⚠️ 이 글자수/이미지 스펙은 `image-style-patterns.md`, `copy-patterns.md`, `kakaopay-banner-guide.md`에도 반영해야 합니다 — 메인 카피 14자는 매우 타이트하므로 카피 생성 스킬의 프롬프트 제약을 이 값으로 맞춰야 합니다. (반영 완료: kakaopay-banner-guide.md)

**Full Screen 배너 소재 폼**은 이번 스크린샷에 포함되지 않음 — TBD. 다만 미리보기상 구성은 헤드라인(예: "3% 돌려드려요!") + 서브카피(혜택 요약) + 기간 정보 + CTA 버튼("혜택 확인하기") 구조로 추정됩니다.


## 3. 에러 표현 — 이 제품의 결정

원본 시스템에는 Error text · Snackbar · Modal · Blockquote가 각각 있지만, **언제
어느 것을 쓸지**는 제품이 정합니다. 셋으로 고정합니다 — 더 늘리면 같은 상황을
화면마다 다르게 알리게 됩니다.

| 방법 | 쓰는 곳 | 원본 컴포넌트 |
|---|---|---|
| **필드 인라인** | 그 칸을 고치면 해결되는 문제 (필수 누락, 형식 오류) | Textfield `State=Error` + Error text |
| **알럿 모달** | 조작이 실패해 되돌릴 게 없는 경우 (업로드 거부) | Modal `Type=Alert` |
| **하단 토스트** | 어디가 문제인지 화면 밖에 있을 때 (제출 시 필수 누락) | Snackbar |

**필드 인라인** — 테두리·배경·입력 텍스트가 함께 붉어지고, 아래 헬퍼 자리에
사유 한 줄(`필수 입력 항목이에요.`)이 붙습니다. 테두리 1px만 바꾸면 화면이 길 때
훑어봐서 어느 칸이 비었는지 안 보입니다.

값은 적지 않습니다 — `textfield.yaml`의 `State=Error`가 정합니다.

**에러를 색만으로 표현하지 않습니다.** 원본의 예외 없는 규칙이고, 반드시 문구를
함께 냅니다. (2026-08-11 감사에서 3곳이 색만 쓰고 있는 것으로 확인됨)

**알럿 모달** — 제목의 줄바꿈은 문구가 정합니다(`whitespace-pre-line`).
브라우저에 맡기면 "파일 형식이 / 아니에요"처럼 끊깁니다.

**진행 버튼은 비활성화하지 않습니다.** 눌러서 무엇이 비었는지 알려주는 편이
낫습니다 — 비활성 버튼은 왜 안 되는지 말해주지 않습니다.

> 이 결정 때문에 하단 CTA는 "비활성처럼 보이지만 눌리는" 버튼이 됩니다. 그래서
> 라벨에 32% 불투명도를 쓰면 안 됩니다(대비 2.14). WCAG의 비활성 면제는 실제로
> 조작할 수 없는 요소에만 적용됩니다.
