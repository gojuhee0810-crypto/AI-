# 하네스와 루프 — 이 프로젝트가 굴러가는 방식

> Claude Code로 서비스를 만들고 고쳐 나가는 구조. **무엇을 하는가(루프)** 와
> **무엇이 있어야 그게 되는가(하네스)** 를 나눠 적는다.
>
> 2026-08-11에 하루치 작업(커밋 19개)을 되짚어 정리했다. 이론이 아니라
> 실제로 무엇이 깨졌고 무엇이 그걸 멈췄는지의 기록이다.

---

## 두 축

| | 루프 | 하네스 |
|---|---|---|
| 언제 | **매 사이클** 반복 | 한 번 세우면 그 위에서 루프가 돈다 |
| 성격 | 동사 — 하는 일 | 명사 — 있는 것 |
| 예 | 구현한다 · 검증한다 · 고친다 | 기준 · 토큰 · 테스트 · CI |
| 없으면 | 일이 안 굴러간다 | **검증 칸이 빈칸이 된다** |

둘을 한 목록에 섞으면 안 된다. 축이 다르다.

### 하네스가 없으면 루프가 헛돈다

2026-08-11 오전에 "디자인 검증"을 했다. 루프는 돌았다. 그런데 기준으로 삼은
문서가 낡아서 **8곳 틀린 값을 그대로 따랐다** — 없는 컴포넌트 스펙, 타입 스케일에
없는 크기, 실측 교체 후에도 남아 있던 "추정치" 경고.

검증이 아무것도 거르지 못했다. 기준이 틀렸기 때문이다.

---

## 하네스 — 먼저 세우고, 계속 자란다

### 1. 기준 — 무엇이 맞는가

```
.claude/skills/adcenter-design-system/   ← 유일한 기준 (별도 저장소를 링크)
src/app/globals.css                      ← 코드가 쓰는 값. 대조 대상
docs/guides/screen-decisions.md       ← 이 제품의 결정만
docs/guides/kakaopay-banner-guide.md     ← 매체 규격 (협상 불가)
```

**기준이 둘이면 반드시 갈라진다.** 그래서 우리 문서에서 겹치는 절반을 걷어냈다.
`CLAUDE.md`의 색인 표가 "무엇을 어디서 찾나"를 라우팅한다.

### 2. 값과 구조 — 두 곳에 없게

| 모듈 | 맡는 것 | 갈라졌던 증거 |
|---|---|---|
| `globals.css` | 색 토큰 | 보조 텍스트 대비 3.47 · 빨강 하나로 2역 |
| `fields.ts` | 폼 여백 · 타입 스타일 | 라벨이 inline이라 116이 113 |
| `buttons.ts` | 버튼 색 3종 | 3색의 뜻이 섞임 |
| `banner-flow.ts` | 진행 판정 · 버튼 색 판단 | 업로드해도 다음 버튼이 안 켜짐 |
| `CharCounter.tsx` | 글자수 | **3벌, 색 3가지** |
| `popup.ts` | 모달 껍데기 | 폭을 정의하고 안 씀 → 258px |
| `api-input.ts` | API 입력 한도 | 검사 자체가 없었음 |
| `FormField.tsx` | 폼 항목 조립 | 라벨 미연결 9곳 · `required` 0건 |

상수는 **값**을 지키고 컴포넌트는 **구조**를 지킨다. 둘은 막는 것이 다르다 —
값이 틀린 게 아니라 *적어야 할 걸 안 적은* 실수는 상수로 못 막는다.

### 3. 게이트 — 통과 조건

```
npm run lint      0
npm test          전부 통과
npm run build     성공
```

**리뷰가 아니라 통과 조건이다.** 여기가 빨간 상태로 리뷰하면 리뷰어가 이미 깨진
코드를 읽는다.

`.github/workflows/ci.yml`이 `main` 푸시와 모든 PR에서 이 셋을 돌린다. 장치를
아무리 만들어도 **누가 돌려야** 돌아가는데, CI가 그걸 사람 기억에서 떼어낸다.

### 4. 회귀 장치 — 고친 게 다시 오지 않게

**같은 실수를 두 번 하면 장치를 만든다**(`CLAUDE.md`). 실제로 두 번을 넘긴 것들이 있다.

| 장치 | 하는 일 |
|---|---|
| 회귀 테스트 | 그 버그가 다시 나면 즉시 실패. 주석이 `회귀:`로 시작 |
| **래칫 테스트** | 현재 위반을 목록으로 기록 → **늘면 실패, 줄어도 실패**("목록 고쳐라") |
| `known-gaps.md` | "고쳐서 해결된 것" 목록. 여기 있는 게 다시 나타나면 **위반이 아니라 회귀** |
| 커밋 메시지 | 왜 그렇게 했는지 + **전에 어떻게 틀렸는지** |

래칫이 필요한 이유: 목록이 비어야 통과하게 만들면 오늘 당장 전부 고쳐야 하고,
그러면 테스트를 아예 안 만들게 된다. 현재 상태를 적어두고 **새로 생기는 것만**
막으면 시작할 수 있다. 실제로 하루에 두 번 발동해 목록이 낡는 걸 막았다.

### 5. 검사 도구

| 도구 | 무엇을 |
|---|---|
| `design-system-auditor` | 하드코딩 색 · 타입 스케일 이탈 · 대비 · 중복 정의 |
| `adcenter-screen-review` | 원본 컴포넌트 28종 스펙과 대조 · 접근성 |
| `adcenter-ux-review` | 규칙이 아니라 "사람이 끝까지 갈 수 있나" |
| Figma MCP | 좌표 실측 |
| 브라우저 | 실제 렌더 측정 |

전부 **고치지 않고 목록만** 낸다. 판단은 사람이 한다.

## 루프 — 이 위에서 돈다

```
  1. 컨텍스트 (PLAN)
       plan · design 문서 → CLAUDE.md

  2. 구현
       2-1  API 연동 (이미지 · 카피)
       2-2  UI/UX (로컬 화면)

  3. 검증
       3-1  기계 — lint · test · build · 감사 에이전트     ← 먼저
       3-2  사람 — 코드 리뷰 · 사용성 리뷰 · 디자인 리뷰

  4. Act
       수정 · 라우팅 룰 · 에이전트 → 커밋
       ↑ 고칠 때 테스트를 같이 단다 → 하네스가 자란다
       └────────────────────────────────────────┘
```

**4번에서 하네스로 돌아가는 화살표가 이 설계의 핵심이다.** 그냥 고치고 끝내면
같은 게 또 온다 — 옐로우 버튼은 세 번, Skeleton 그라데이션은 두 번 깨졌고,
테스트를 같이 달았을 때만 멈췄다.

### 검증을 둘로 가르는 이유

| | 무엇 | 누가 |
|---|---|---|
| 기계 검증 | 값이 맞나 | 도구 |
| 사람 검증 | 이게 좋은가 | 판단 |

**기계가 먼저다.** 두 가지 이유가 있다.

1. 기계가 찾는 것 중 상당수가 **구조를 바꾼다**(중복 정의 통합 등). 사람 리뷰를
   먼저 하면 곧 바뀔 코드를 읽게 되고, 리뷰를 두 번 하거나 안 본 코드를 배포한다.
2. 기계는 거의 공짜고 사람 리뷰는 주의력을 쓴다. **싸고 확실한 것부터** 걷어내고
   남은 것에 주의력을 쓴다.

### 순서 규칙 — 어겨서 배운 것

| 규칙 | 어겼을 때 |
|---|---|
| 게이트가 먼저 | 빨간 상태로 리뷰하면 그것부터 지적하고 끝난다 |
| 기계 검사 → 사람 리뷰 | 리뷰한 코드가 아닌 게 남는다 |
| 구조 먼저 → 값 나중 | 리뷰가 최종 코드를 못 본다 |
| **화면 전환 먼저 → 공용 상수 나중** | 공용 간격을 먼저 바꿨더니 아직 안 바꾼 화면이 전부 좁아졌다 |
| **한 번에 한 필드씩 바꾸고 화면 확인** | 화면 하나를 통째로 바꿨다가 되돌렸다 |

## 런타임에도 루프가 있다

개발 루프만 있는 게 아니다. **제품 안에서도** 생성→검사→재시도가 돈다.

```
카피 생성
  ① Claude 1콜 — 패턴별 3안
  ② 코드가 검사       글자수 15/14 · 문구 중복 · 오브젝트명 재노출 · 규제 표현
  ③ 위반 0 → 반환                          ← 대부분 여기 (1콜)
     위반 있음 → Claude 보정 콜 (위반 필드만) → 다시 검사
  ④ 그래도 남으면 경고만 찍고 반환           ← 무한 루프 방지
```

**종료 조건**: 위반 0, 또는 보정 1회 후 포기.

### 틀림을 세 종류로 가른다

| 종류 | 어떻게 | 예 |
|---|---|---|
| 코드가 확인 가능 | 검사 → 틀리면 다시 시킴 (루프) | 글자수 · 중복 · 금칙어 |
| 확인은 어렵고 예방은 가능 | 프롬프트 규칙으로 사전 차단 | 혜택 수치 왜곡 |
| 판단이 필요 | 사람이 고름 | 셋 중 뭐가 나은가 |

**LLM에게 검사를 시키지 않는다.** LLM은 글자를 못 센다 — 검사는 코드가 하고,
LLM은 "다시 써라"는 지시만 받는다. 원래는 검증도 Claude 호출이었는데 기준 넷이
전부 기계적이라는 걸 알고 코드로 내렸다. 정상이면 1콜, 문제 있을 때만 2콜이 됐다.

### 이미지에는 이 루프가 없다

규격(240×240)은 `sharp`가 강제하지만, **나온 그림이 오브젝트를 맞게 그렸는지는
아무도 안 본다.** `style1-generate` · `style2-generate` · `prompt-compiler`에
테스트도 없다. 알고 있는 구멍이다.

## 두 개의 세계 — 헷갈리기 쉬운 것

```
┌─ 개발할 때 ────────────────────────┐
│  .claude/agents/  .claude/skills/  │
│  → Claude Code(개발자)에게만 보인다  │
└────────────────────────────────────┘
                ↓ 코드를 짠다
┌─ 제품이 돌 때 ─────────────────────┐
│  src/                              │
│  → .claude/ 를 참조하지 않는다      │
└────────────────────────────────────┘
```

`.claude/agents/`의 에이전트는 **광고주가 버튼을 눌러도 돌지 않는다.**
`src/`가 `.claude/`를 참조하는 코드는 한 줄도 없다(2026-08-11 확인).

`image-research-agent` · `copy-research-agent`의 description이 한때 "생성 직전에
호출된다"고 적혀 있었다(2026-08-13 수정). 런타임에서 같은 일을 하는 것은 각각
`prompt-compiler.ts`의 `resolveObjectBlueprint()`와 `copy-generate.ts`다 —
**기능은 있었고 적힌 경로가 틀렸다.** 두 에이전트는 개발용으로 남긴다.

## 아직 없는 것

| 구멍 | 뜻 |
|---|---|
| **화면 렌더 테스트 일부만** | 2026-08-13에 `FormField`·`buttons` 21개를 덮었다(`react-dom/server`, 새 의존성 없음). 나머지 컴포넌트는 아직 없고 상호작용은 못 본다 |
| **이미지 생성 검증 없음** | 규격만 강제. 내용은 아무도 안 본다 |
| **실제 API 미검증** | 개발 서버가 `MOCK_AI=1`. 실제 호출 경로는 오늘 한 번도 안 돌았다 |
| **심볼릭 링크가 로컬 전용** | 다른 컴퓨터에서는 기준 자체가 없다(테스트는 건너뛰게 막아둠) |

화면 렌더 테스트가 없다는 게 실제로 문제가 됐다. `FormField`로 1단계를 바꿀 때
타입·테스트·빌드가 전부 통과했고 서버 HTML의 속성 개수까지 셌지만, **화면을 안 봤다.**
간격이 이상해진 걸 찾은 건 사용자였다.

2026-08-13에 그 `FormField`부터 렌더 테스트를 달았다. 감사에서 나왔던 항목
(라벨 미연결 · `required` 0건 · `aria-invalid` 누락)이 그대로 테스트 이름이 됐고,
일부러 되돌려 넣어 네 가지가 전부 실패하는 것까지 확인했다 — **통과만 하고 회귀를
못 잡는 테스트는 없느니만 못하다.** 다만 서버 렌더라 간격은 여전히 못 본다.
그걸 재는 건 브라우저뿐이다.

그래서 규칙 하나: **화면이 바뀌면 브라우저에서 재고, 못 쟀으면 "확인 못 함"이라고
적는다.** "브라우저 실측"과 "타입·테스트만 통과"를 구분해서 말한다.
