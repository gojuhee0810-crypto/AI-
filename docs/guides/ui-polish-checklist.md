# UI 폴리시 체크리스트 — `make-interfaces-feel-better` 적용 검토

> 설치일 2026-08-07. 이 문서는 "이 스킬을 적용하면 우리 화면이 어떻게 달라지는가"를
> 실제 파일 기준으로 정리한 것입니다. 스킬 원문은
> `.agents/skills/make-interfaces-feel-better/`에 있습니다.

## 1. 토큰 비용

측정값(`wc -m` 기준, 영어 텍스트라 대략 4자 ≈ 1토큰):

| 파일 | 문자 수 | 대략 토큰 | 언제 읽히나 |
|---|---:|---:|---|
| (설명 한 줄) | ~400 | ~100 | **항상** — 세션마다 고정 |
| `SKILL.md` | 11,818 | ~3,000 | 스킬을 호출할 때만 |
| `animations.md` | 12,711 | ~3,200 | 애니메이션 작업 시에만 |
| `surfaces.md` | 7,239 | ~1,800 | 그림자·radius 작업 시에만 |
| `typography.md` | 4,690 | ~1,200 | 텍스트 작업 시에만 |
| `performance.md` | 3,046 | ~800 | 성능 작업 시에만 |
| `icons.md` | 2,277 | ~600 | 아이콘 작업 시에만 |
| **전부 읽을 때 합계** | 41,781 | **~10,500** | |

**결론: 평소엔 거의 안 먹습니다.** 항상 로드되는 건 설명 한 줄(~100토큰)뿐이고,
본문은 UI 작업을 할 때만 읽힙니다. 하위 5개 파일은 해당 주제를 다룰 때만 열립니다.

비교하자면 이 프로젝트의 `copy-generate.ts` 프롬프트 한 번 호출이 ~1,500토큰입니다.
스킬을 한 번 호출하는 비용(~3,000)은 카피 생성 두 번 정도입니다. 화면 작업할 때만
쓰면 비용 문제는 아닙니다.

## 2. 우리 화면에서 실제로 바뀌는 것

현재 코드를 스캔해서 나온 실제 항목만 적습니다. 심각도 순.

### HIGH — 지금 문제가 되는 것

| 위치 | Before | After | 왜 |
|---|---|---|---|
| `AdStudioShell.tsx:37` 사이드바 접기 버튼 | `h-6 w-6` (24×24px) | 최소 40×40px 히트 영역 | 24px는 마우스로 정확히 못 누릅니다. 스크린샷에서 이 버튼이 안 보였던 것도 같은 이유 |
| `Step1ImagePanel.tsx` "또는 직접 업로드" | 텍스트만 (높이 ~16px) | `min-h-10` + 패딩 | 클릭 대상이 글자 높이뿐이라 누르기 어려움 |

### MEDIUM — 눈에 띄는 흔들림

| 위치 | Before | After | 왜 |
|---|---|---|---|
| `Step2CopyPanel.tsx:81,172,188` 글자수 카운터 | `{length}/15` | `tabular-nums` 추가 | `1/15` → `10/15`로 바뀔 때 숫자 폭이 달라져 텍스트가 흔들립니다 |
| `PreviewPanel.tsx:27` 금액 `100,067원` | 일반 숫자 | `tabular-nums` | 미리보기 금액이 바뀔 때 레이아웃이 밀림 |
| `page.tsx:110` 등 버튼 `transition` | 속성 전체 전환 | `transition-[background-color,scale]` | 의도하지 않은 속성까지 애니메이션돼서 반응이 둔해 보임 |

### LOW — 체감 마감도

| 위치 | Before | After | 왜 |
|---|---|---|---|
| 모든 버튼 | 누를 때 변화 없음 | `active:scale-[0.96]` | 눌렸다는 촉각적 피드백 |
| 이미지 카드 | `border border-line` | 레이어드 `box-shadow` | 테두리는 "구조"용, 깊이는 그림자로 — 카드가 떠 보임 |
| 카드 안 이미지 영역 | 바깥·안쪽 radius 동일 | 바깥 = 안쪽 + 패딩 | 중첩 모서리가 안 맞으면 안쪽이 찌그러져 보임 |
| 제목·본문 | 기본 줄바꿈 | `text-balance` / `text-pretty` | 제목 끝에 한 단어만 떨어지는 것 방지 |

### 이미 되어 있던 것

- `layout.tsx:28` — `antialiased` 이미 적용 ✅
- `StepIndicator.tsx` 체크 아이콘 — `currentColor` + `strokeWidth 2`(bold 텍스트와 일치) ✅

## 3. 적용하지 않기로 한 것

| 원칙 | 이유 |
|---|---|
| **이미지 아웃라인**(1px 검정 10%) | 우리 이미지는 배경이 제거된 투명 PNG입니다. 아웃라인을 넣으면 오브젝트가 아니라 빈 사각형에 테두리가 그려져서 오히려 지저분해집니다 |
| **`initial={false}` on AnimatePresence** | `framer-motion`을 안 씁니다. 불필요한 라이브러리를 추가하지 않는다는 프로젝트 규칙에도 어긋납니다 |
| **`will-change`** | 아직 첫 프레임 끊김이 관측되지 않았습니다. 관측 전에 넣으면 메모리만 씁니다 |
| **스태거 등장 애니메이션** | 이미지 2장·카피 3장이 동시에 나오는 건 순서가 의미를 갖지 않습니다. 스킬 자체도 "빈번한 상호작용엔 쓰지 말 것"이라고 합니다 |

## 4. 스킬을 쓸 때의 원칙

- **화면 구조가 확정된 뒤에 돌립니다.** 구조를 바꾸면 폴리시 작업이 통째로 날아갑니다
- **한 번에 한 화면씩.** `quick` 모드는 상위 5개, `full`은 15개까지 지적합니다
- **스타일 시스템을 섞지 않습니다.** 이 프로젝트는 Tailwind이므로 수정도 Tailwind로만 표현합니다(스킬 본문에도 명시된 규칙)
