## 이 문서의 범위

**여기 적는 것**: 코드만 봐서는 알 수 없는 것 — 왜 그렇게 정했는지, 매체가 강제하는
제약, 의도적으로 뺀 기능.

**여기 적지 않는 것**: 컬러 hex·spacing·폰트 토큰. 그건 `src/app/globals.css`가 유일한
진실이며, 문서에 옮겨 적으면 코드와 반드시 어긋난다. 컴포넌트 생김새도 코드가 곧 스펙이다.

## Context Anchor

| Key | Value |
|-----|-------|
| **WHY** | 비디자이너 광고주가 이미지·카피·조합을 한 흐름에서 끝내게 한다. 화면을 오가며 규격을 맞추다 반려되는 왕복을 없앤다 |
| **WHO** | 카카오페이 광고주 중 Fit 배너 소재를 직접 등록하는 담당자 |
| **RISK** | 이미지·카피 생성이 각각 수십 초 걸린다. 대기 중 이탈하면 앞 단계 결과가 전부 날아간다(현재 state는 메모리에만 존재) |
| **SUCCESS** | 오브젝트·혜택 두 번의 입력만으로 매체 규격을 만족하는 소재 1건이 완성되고, 그 결과가 미리보기에서 실제 노출 모습으로 확인된다 |
| **SCOPE** | 소재 "제작"까지. 광고센터 등록 연동은 별도 feature(미착수) |

## 1. 화면 구조

```
┌──────────────────────────────────────────────────────────────┐
│ 검정 헤더 (pay | 광고센터)                     이메일 · 로그아웃 │
├───────────┬──────────────────────────────────────────────────┤
│           │ AI 광고 배너 스튜디오                              │
│  다크     │ ①이미지 생성 ── ②카피 문구 ── ③최종 선택          │
│  사이드바 ├────────────────────────────┬─────────────────────┤
│           │                            │                     │
│           │   좌: 단계별 폼  (flex 6)   │  우: 미리보기 (flex 4)│
│           │                            │                     │
│           ├────────────────────────────┴─────────────────────┤
│           │ 취소                         [이전] [다음 단계]    │
└───────────┴──────────────────────────────────────────────────┘
```

구현: [page.tsx](../../../src/app/(studio)/ai-banner/page.tsx)

### 확정된 제약 (변경 시 사용자 확인 필수)

| 제약 | 근거 |
|---|---|
| **미리보기는 반드시 오른쪽에 상시 노출** | 사용자가 "무조건 지켜야 한다"고 명시(2026-08-06). 만든 소재가 실제로 어떻게 보이는지 즉시 확인하는 것이 이 화면의 존재 이유 |
| **좌:우 = 6:4** | 2026-08-07 확정 |
| **3단계 스테퍼** | 1·2단계는 생성 액션, 3단계는 취합 검토. 3단계 필요성은 사용성 검토에서 확인됨(아래 §3) |
| 헤더·사이드바는 검정 | 광고센터 어드민과 같은 셸을 쓴다 — 별도 서비스가 아니라 광고센터의 한 기능으로 인식돼야 함 |

## 2. 단계별 책임

| 단계 | 입력 | 호출 | 다음 단계 조건 |
|---|---|---|---|
| **1. 이미지 생성** | 오브젝트 명칭(15자) | `POST /api/generate-image` — 스타일1(3D)·스타일2(2D) 동시 | 이미지 1장 이상 생성됨 |
| **2. 카피 문구** | 캠페인 혜택(25자) | `POST /api/generate-copy` — 패턴별 3안 | 카피 1개 선택됨 |
| **3. 최종 선택** | 없음(검토만) | 없음 | 항상 통과 |

State 정의는 `AiBannerFlowState`([page.tsx](../../../src/app/(studio)/ai-banner/page.tsx))가 유일한 진실.

### 매체 규격 (카카오페이 Fit 배너 — 협상 불가)

| 항목 | 제한 |
|---|---|
| 메인 카피 | **14자** (공백 포함) |
| 서브 카피 | **15자** (공백 포함) |
| 이미지 | PNG · **240×240px** · 500KB 이하 |

이 값은 코드 3곳(생성 프롬프트, `validateRecommendations`, 인라인 수정 카운터)에 흩어져
있으므로 변경 시 전부 함께 고쳐야 한다.

## 3. 사용성 검토로 확정된 결정

| 결정 | 이유 |
|---|---|
| **3단계를 유지한다** | 제거를 두 번 제안했으나 두 번 다 근거가 틀렸다. 1·2단계는 각각 "생성하고 고르는" 작업 화면이고, 3단계는 이미지+카피가 합쳐진 최종 결과를 한 번에 확인하는 유일한 지점이다 |
| **3단계에 타겟팅 정보를 넣지 않는다** | 앞 단계에 타겟 입력이 없는데 3단계에서 갑자기 나오면 출처가 불명확해 혼란을 준다(2026-08-06 사용자 지적) |
| **"카피 변경하기"를 추가한다** | 레퍼런스에는 "이미지 변경하기"만 있어 비대칭이었다. 3단계에서 카피만 고치고 싶을 때 되돌아갈 길이 없었음 |
| **타겟 입력 폼을 만들지 않는다** | 원래 설계상 타겟은 앞 단계(광고그룹)에서 정해져 넘어온다. 그 흐름이 생기기 전까지 전 사용자를 `2030세대`로 가정하고 서버가 기본값을 채운다 |
| **브랜드 컬러 선택을 제거한다** | 2026-08-07 확정. 생성 이미지 스타일이 이미 고정돼 있어 실효가 없었다 |

## 4. 상태 표현 규칙

코드 여러 곳에 반복되므로 규칙으로 고정한다.

**스테퍼** — 완료: 검정 원 + 체크 / 현재: 브랜드 옐로우 + 숫자 / 예정: 회색 테두리 + 숫자.
연결선도 완료 구간만 검정.

**버튼 색** — **지금 눌러야 진행되는 버튼 하나만 옐로우.** 나머지는 회색.
1단계에서 이미지를 만들기 전에는 "AI 이미지 생성하기"가 옐로우이고, 만들고 나면
주요 액션이 "다음 단계"로 넘어가므로 생성 버튼은 회색으로 내려간다. 화면에 옐로우
버튼이 둘 이상 보이면 규칙 위반이다.

**생성 대기** — 결과와 같은 모양의 스켈레톤으로 자리를 미리 잡고(레이아웃 점프 방지),
진행 문구를 순환시킨다. 이미지·카피 모두 수십 초가 걸려 빈 화면이면 멈춘 것처럼 보인다.
구현: [GenerativeLoading.tsx](../../../src/components/ai-banner/GenerativeLoading.tsx)

세부 폴리시 기준은 [ui-polish-checklist.md](../../guides/ui-polish-checklist.md) 참고.

## 5. 준비 중 표시만 하고 동작하지 않는 것

화면에는 있지만 의도적으로 비활성인 항목들. 제거하지 않은 이유는 최종 폼의 전체 모습을
보여주기 위함이다.

| 항목 | 상태 |
|---|---|
| 이미지 직접 업로드 | 비활성 · "준비 중" |
| 배너 강조 요소 — 로고 / 혜택 배지 | 선택은 되지만 결과물에 반영 안 됨 |
| 3단계 "소재 등록하기" | 광고센터 연동 미착수 — 누르면 아무 일도 일어나지 않음 |

## 6. 남은 과제

| 과제 | 메모 |
|---|---|
| **카피 대기시간 단축** | 현재 20~40초. 패턴 단위 스트리밍(SSE)으로 첫 카드 ~7초까지 줄일 수 있다. 검증을 통과한 패턴만 화면에 추가해야 카피가 눈앞에서 바뀌는 일을 막을 수 있다 |
| **미리보기 정확도** | 지금은 DOM으로 근사 재현. 실제 앱 목업 PNG를 배경으로 깔고 배너 영역만 오버레이하는 방식으로 교체 예정 |
| **한글 폰트** | 현재 Geist(라틴 전용)라 한글은 시스템 폰트로 폴백된다. 실제 앱과 다르게 보임 |
| **디자인 토큰 정밀화** | `globals.css`의 값은 스크린샷 기반 추정치. Figma MCP 연동 시 실측값으로 교체 |
| **이탈 시 데이터 소실** | state가 메모리에만 있어 새로고침하면 전부 사라진다. 생성 비용이 드는 결과이므로 보존 방안 필요 |
| **광고센터 등록 연동** | 별도 feature |
