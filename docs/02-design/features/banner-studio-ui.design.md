## 이 문서의 범위

**여기 적는 것**: 코드만 봐서는 알 수 없는 것 — 왜 그렇게 정했는지, 매체가 강제하는
제약, 의도적으로 뺀 기능.

**여기 적지 않는 것**: 컬러 hex·spacing·폰트·컴포넌트 스펙. 그건
`.claude/skills/adcenter-design-system/`이 유일한 기준이고, `src/app/globals.css`가
코드가 실제로 쓰는 값이다. 문서에 옮겨 적으면 반드시 어긋난다.

> 이 규칙은 두 번 실패해서 나왔다. 이 문서의 이전 판과 `admin-design-system.md`가
> 사이드바를 "거의 블랙"이라고 적어둔 탓에 사이드바를 검정으로 만들었고(실제 `#f8f9fa`),
> 2026-08-11 감사에서 `admin-design-system.md`가 **8곳 더 틀린 채** 기준 노릇을
> 하고 있는 게 드러났다 — 없는 컴포넌트 스펙, 타입 스케일에 없는 크기, 실측 교체 후에도
> 남아 있던 "추정치" 경고. 그래서 그 문서에서 겹치는 절반을 걷어냈다.
> **틀린 문서는 없는 문서보다 나쁘다.**

## Context Anchor

| Key | Value |
|-----|-------|
| **WHY** | 비디자이너 광고주가 이미지·카피·조합을 한 흐름에서 끝내게 한다. 화면을 오가며 규격을 맞추다 반려되는 왕복을 없앤다 |
| **WHO** | 카카오페이 광고주 중 Fit 배너 소재를 직접 등록하는 담당자 |
| **RISK** | 이미지·카피 생성이 각각 수십 초 걸린다. 대기 중 이탈하면 앞 단계 결과가 날아간다 → `sessionStorage` 보존으로 해소(§5) |
| **SUCCESS** | 오브젝트·혜택 두 번의 입력만으로 매체 규격을 만족하는 소재 1건이 완성되고, 그 결과가 미리보기에서 실제 노출 모습으로 확인된다 |
| **SCOPE** | 소재 "제작"과 등록 정보 입력까지. 광고센터 등록 API 연동은 별도 feature(미착수) |

### 확정된 제약 (변경 시 사용자 확인 필수)

| GNB는 검정, LNB는 밝은 회색 | Figma 실측(`--color-header` / `--color-sidebar`). 광고센터와 같은 셸을 쓴다 — 별도 서비스가 아니라 광고센터의 한 기능으로 인식돼야 함 |

## 2. 단계별 책임

| 단계 | 입력 | 호출 | 다음 단계 조건 |
|---|---|---|---|
| **1. 이미지 생성** | 소재 이름(25자) → 이미지 유형 → 오브젝트 명칭(15자) 또는 제품 이미지 업로드 → 강조 요소 | `POST /api/generate-image` — 3D·2D 동시 | 그래픽: 스타일 선택 / 제품: 업로드 완료 |
| **2. 카피 문구** | 캠페인 혜택(25자) | `POST /api/generate-copy` — 패턴별 3안 | 카피 1개 선택됨 |
| **3. 소재 등록** | 안내 문구(60자) · **랜딩 URL(필수)** · 심사 참고사항(500자) | 없음(등록 연동 미착수) | 랜딩 URL이 `https://` 형식 |

**소재 이름만 먼저 받는다.** 2026-08-10에 입력 순서 강제를 걷어냈다 — 손대지도 않은
칸이 먼저 혼내는 꼴이었다. 대신 2026-08-11에 소재 이름 하나만 예외로 되돌렸다:
비운 채 칸을 벗어나거나(blur) 이미지를 만들려 하면 그 자리에서 알린다. 이름 없이 만든
이미지는 나중에 무엇을 위한 소재였는지 알 수 없고, 3단계 등록에서 어차피 막힌다.

나머지 빈 필수 칸은 하단 CTA를 눌렀을 때만 붉어진다(`showErrors`).

> 이건 원본 시스템의 "빈 칸은 제출 시에만" 규칙에서 의도적으로 벗어난 것이다.

### 판정은 한 곳에서만 한다

`isStepComplete` / `resolveBannerImageUrl` / `resolveObjectTag` / `isValidLandingUrl`
— 전부 [banner-flow.ts](../../../src/types/banner-flow.ts)에 있다.

이렇게 모은 이유가 있다. 제품 이미지 업로드 경로를 추가하면서 "다음 단계" 조건을
`images.length > 0`으로 둔 채로 두었더니, 업로드를 마쳐도 버튼이 안 켜졌다. 같은
원인으로 미리보기 이미지와 `objectTag`까지 세 곳이 함께 깨져 있었다.
**분기를 화면에 흩어놓으면 한쪽만 고치게 된다.** 회귀 테스트 12개가 이 규칙을 지킨다.

### 매체 규격 (카카오페이 Fit 배너 — 협상 불가)

| 항목 | 제한 |
|---|---|
| 메인 카피 | **14자** (공백 포함) |
| 서브 카피 | **15자** (공백 포함) |
| 이미지 | PNG · **240×240px** · 500KB 이하 |
| 로고 | PNG(투명) · 1MB 이하 |

메인·서브 글자수는 코드 3곳(생성 프롬프트, `validateRecommendations`, 인라인 수정
카운터)에 흩어져 있으므로 변경 시 전부 함께 고쳐야 한다.

## 3. 사용성 검토로 확정된 결정

| 결정 | 이유 |
|---|---|
| **3단계를 유지한다** | 한때 "확인만 하는 화면"이라 없애자고 봤다. 등록 정보(안내 문구·랜딩 URL·심사 참고사항)가 들어오면서 **여기서만 할 수 있는 일**이 생겨 근거가 사라졌다 |
| **스테퍼 3단계 이름은 "소재 등록"** | "최종 선택"이었으나 3단계에서 고르는 게 없다. 선택이라고 부르면 뭘 더 골라야 하나 찾게 된다 |
| **3단계에 타겟팅 정보를 넣지 않는다** | 여기서 고칠 수 없는 값이다. 발견해도 광고그룹으로 돌아가야 해서 만들던 소재가 날아간다. 헤더의 캠페인·광고그룹과 성격이 같아 3단계에만 카드로 세우면 여기서 정하는 것처럼 보인다(2026-08-09 확정) |
| **3단계에 재질·시점을 넣지 않는다** | 사용자가 고른 적 없는 값이다. 화면에 적으면 지어낸 정보가 된다 |
| **혜택 배지는 텍스트가 아니라 그래픽** | 서브타이틀 옆에 두면 카피 자리를 뺏는다. 이미지 좌하단에 얹는 원형 스티커로 만들고 사용자는 문구와 색만 정한다 |
| **선택 표시는 라디오 하나로만** | 테두리 색까지 함께 바뀌니 인풋 포커스 표시와 뒤섞여 오히려 무엇이 선택된 건지 흐려졌다. 호버는 연한 회색 배경만 |
| **카피 3안은 카드가 아니라 한 목록** | 같은 질문에 대한 답이라 목록으로 읽혀야 비교가 된다. 카드로 떼어놓으면 각각 독립된 것처럼 보여 눈이 셋을 오가지 않는다 |
| **카피 수정 버튼은 선택된 카드에만** | 셋 다 달면 아직 안 고른 카피까지 손댈 수 있는 것처럼 보여, 비교해야 할 자리에서 편집을 먼저 하게 된다 |
| **타겟 입력 폼을 만들지 않는다** | 타겟은 앞 단계(광고그룹)에서 정해져 넘어온다. 그 흐름이 생기기 전까지 전 사용자를 `2030세대`로 가정하고 서버가 기본값을 채운다 |
| **브랜드 컬러 선택을 제거한다** | 2026-08-07 확정. 생성 이미지 스타일이 이미 고정돼 있어 실효가 없었다 |

## 4. 상태 표현 규칙

코드 여러 곳에 반복되므로 규칙으로 고정한다.

**스테퍼** — 완료: 검정 원 + 체크 / 현재: 검정 원 + 숫자 + 굵게 / 예정: 회색 + 흐린 숫자.
완료한 단계만 눌러서 되돌아갈 수 있다.

**버튼 색** — 색은 셋뿐이고 뜻이 겹치지 않는다(2026-08-11 사용자 버튼 가이드).

| | 뜻 |
|---|---|
| `brand` | 지금 눌러야 진행된다. **화면에 하나만** |
| `support` | 누를 수 있지만 주인공은 아니다 |
| `disabled` | 정말 못 누른다. 라벨 32% |

AI 생성 버튼은 네 단계를 돈다 — ① 입력 전 `disabled` ② 입력 후 `brand`
③ 생성 중 `brand`+로딩 ④ 완료 후 `support`.

**판단은 `resolveButtonTone` 하나가 한다.** 화면이 스스로 정하면 어긋난다 — 세 번
깨졌고, 마지막엔 "누를 수 있는 다시 생성하기"에 옅은 노랑을 써서 못 누르는 버튼과
같은 색이 됐다. 조합 4,608개를 도는 테스트가 "옐로우가 둘"을 막는다.

옅은 노랑의 라벨 32%는 `disabled:` 접두사 뒤에 있다. 하단 CTA는 비활성처럼 보여도
눌러서 무엇이 비었는지 알려주는 버튼이라, 조작 가능한 요소에는 WCAG 면제가 없다.

**구분선** — 한 상자 안에서 항목을 나누는 선은 `#cfd6dc` 1px 하나뿐이다(`.divider-rows`).
좌우로 거터만큼 물러나 글이 시작하는 자리에서 함께 시작한다 — 상자 테두리까지 닿으면
바깥 테두리와 이어져 격자처럼 보인다.

거터는 컨테이너의 `--gutter`(기본 20)가 정하고, 행의 좌우 여백과 **같은 값**을 본다.
둘을 따로 적으면 한쪽만 고쳤을 때 선이 혼자 남는다.

2026-08-11에 양 끝을 흐리던 그라데이션을 걷어냈다. 시스템의 구분선은 실선 한 종류뿐이고,
흐린 선은 같은 자리에 두 가지 선이 있는 것처럼 보였다. 선은 배경 채우기가 아니라
`border-top`으로 그린다 — 1px 배경은 줌 배율에 따라 굵기가 갈린다.

**글자수 카운터** — 초과해도 검정을 유지한다([CharCounter.tsx](../../../src/components/ai-banner/CharCounter.tsx)).
입력칸이 이미 테두리·배경·글자로 붉게 알리는데 카운터까지 붉어지면 값이 문제인지
길이가 문제인지 흐려진다.

**생성 대기** — 결과와 같은 모양의 스켈레톤으로 자리를 미리 잡고(레이아웃 점프 방지),
진행 문구를 순환시킨다. 이미지·카피 모두 수십 초가 걸려 빈 화면이면 멈춘 것처럼 보인다.
구현: [GenerativeLoading.tsx](../../../src/components/ai-banner/GenerativeLoading.tsx)

세부 폴리시 기준은 [ui-polish-checklist.md](../../guides/ui-polish-checklist.md) 참고.

## 4-2. 폼 항목의 구조

값(50·15·12·6)은 원본 해부도 그대로다. 그 값은 이 문서가 정하지 않는다 —
`.claude/skills/adcenter-design-system/1-components/form/form-field.yaml`이 정한다.

여기 적는 건 **우리가 그걸 어떻게 강제하는가**다.

```
FormField
  ├ 라벨 (Title 18/Bold) + *
  ├ 설명 (Body 14/Regular)     ← 간격 0. 라벨에 붙는다
  │  ↓ space/15
  └ 컨트롤
     ├ 선택지 A                ← 그룹이면 FormOptions
     │  ↓ space/12
     └ 선택지 B
     ↓ space/6
     헬퍼 / 카운터
  ↓ space/50
```

**손으로 조립하지 않는다.** 상수만 두고 화면이 조립하던 때 이렇게 갈렸다 —
`FieldLabel`이 두 벌인데 한쪽만 `*`를 붙였고, 라벨이 연결 안 된 입력이 다섯 개였고,
`required`는 전 화면에 하나도 없었고, 설명 문구가 세 군데로 흩어졌다.
전부 값이 틀린 게 아니라 **적어야 할 걸 안 적은 것**이라, 상수로는 못 막는다.

- `required`가 `*`·`required`·`aria-required`를 함께 건다
- `error`가 `aria-invalid`·`aria-describedby`를 함께 건다
- `htmlFor`는 단일 컨트롤일 때 **타입이 강제**한다. 라디오 그룹은 `as="group"`으로
  `<fieldset><legend>`가 된다 — 가리킬 컨트롤이 하나가 아니면 `<label for>`를 쓸 수 없다
- `error={null}`은 "지금은 없지만 생길 수 있다"는 뜻이라 헬퍼 줄이 자리를 지킨다.
  아예 안 넘기면 그 항목은 에러를 내지 않는 것으로 보고 줄을 만들지 않는다

구현: [FormField.tsx](../../../src/components/ai-banner/FormField.tsx) ·

## 4-3. API 입력 한도

화면의 `maxLength`는 브라우저를 거친 요청만 막는다. 라우트가 길이를 안 보면 요청 하나로
Claude에 임의 길이를 넘길 수 있고, LLM 엔드포인트에서 그건 곧 토큰 비용과 지연이다.

| 값 | 한도 | 화면 쪽 |
|---|---|---|
| `objectTag` / `primaryObject` | 15 | 오브젝트 명칭 |
| `benefit` | 25 | 캠페인 혜택 |
| `target` | 50 | 화면 입력 없음(서버 기본값) |
| 재질·브랜드컬러·시각화 노트 | 100 | 화면 입력 없음 |

- 한도는 화면 입력칸과 **같은 값**이다. 여유를 두지 않는다 — 여유는 곧 검사하지 않는 구간이다
- 넘으면 **자르지 않고 거절**한다. 잘라 넘기면 적은 것과 다른 결과가 나오는데 왜 다른지 화면에 안 나온다
- 실패 응답에 업스트림 메시지를 싣지 않는다. SDK 예외에는 상위 URL·조직 ID·키 조각이 섞일 수 있고, 이 화면은 그 문구를 그대로 보여준다. 원문은 서버 로그에만

구현: [api-input.ts](../../../src/lib/api-input.ts) · 테스트 4개

## 5. 미리보기 구성

목업 PNG(1125×2436)를 **배너 자리에서 위·아래로 잘라** 그 사이에 배너를 끼운다.
통짜 이미지 위에 배너를 얹으면 안내 문구(심의필)가 붙어 배너가 세로로 늘어날 때
아래 앱 화면이 밀리지 않고 덮인다 — 실제 앱에서는 밀려 내려간다.

- 배너 여백은 목업에 원래 그려져 있던 배너를 잘라 실측했다(1026×275 기준 좌 74px, 우 49px)
- 배너 높이는 고정하지 않는다. 안쪽 여백과 내용이 정한다
- 목업에 구워진 "새 피드" 플로팅 버튼은 흰 사각형으로 덮는다 — 우리 소재와 무관한 앱 UI인데 배너 바로 아래라 시선을 끈다
- 앱 화면 전체에 흰 딤을 씌우고 배너만 선명하게 남긴다

구현: [PreviewPanel.tsx](../../../src/components/ai-banner/PreviewPanel.tsx)

### 새로고침 보존

`sessionStorage`에 저장한다(`localStorage` 아님). 새로고침은 버티되 탭을 닫으면 지운다 —
일주일 전 만들다 만 배너가 갑자기 되살아나는 편이 더 혼란스럽다.

- 진행 중 플래그는 저장하지 않는다. 복원하면 이미 죽은 요청을 기다리는 스피너가 영원히 돈다
- 단계는 데이터가 허용하는 범위로 낮춘다. 저장된 단계가 3인데 이미지가 없으면 사용자가 갇힌다
- 용량 초과 시 업로드 이미지만 빼고 재시도한다. 이미지는 다시 올릴 수 있지만 40초 걸려 만든 카피는 그렇지 않다

구현: [flow-state-storage.ts](../../../src/lib/flow-state-storage.ts) · 테스트 11개

## 7. 남은 과제

| 과제 | 메모 |
|---|---|
| **카피 대기시간 단축** | 현재 20~40초. 패턴 단위 스트리밍(SSE)으로 첫 카드 ~7초까지 줄일 수 있다. 검증을 통과한 패턴만 화면에 추가해야 카피가 눈앞에서 바뀌는 일을 막을 수 있다 |
| **업로드 이미지 보관** | 지금은 data URL이라 sessionStorage 용량을 먹는다. Supabase Storage로 옮기면 해소 |
| **광고센터 등록 연동** | 별도 feature. 3단계 등록 정보(안내 문구·랜딩 URL·심사 참고사항)는 이미 state에 있다 |
| **Full Screen 배너 폼** | 해당 Figma 프레임 미확보 |
| **원본 컴포넌트로 교체** | Empty State·Blockquote·Stepper Item·Snackbar를 직접 만들어 쓰고 있다. 2026-08-11 감사 §1 참고 — 화면이 눈에 띄게 바뀌므로 별도로 진행 |
| **자간(letter-spacing)** | `TEXT` 상수는 만들었지만 화면 대부분이 아직 개별 값을 조합한다. 넷 중 하나가 빠지면 원본과 어긋난다 |
| **남은 중복** | 빈 상태 3벌·불릿 목록 3벌(이미 색이 갈라짐)·support 버튼 3벌·Primary disabled 2벌 |
| **기존 취약점** | `npm audit` high 3(lodash·postcss) + moderate 2. 이번 작업과 무관하고 `audit fix`가 깰 수 있어 따로 봐야 한다 |
